Dashboard / พื้นที่บัญชีผู้ใช้ — 4 ทิศทางดีไซน์

ครอบคลุมทั้ง 7 หน้า (คำสั่งซื้อ · บัญชี · การแจ้งเตือน · ใบเสร็จ · คูปอง · รายการโปรด · เครดิต) — แต่ละแบบกำหนด โครงหน้า (shell) ที่ใช้ร่วมกันทุกหน้า แล้วสาธิตด้วยหน้าคำสั่งซื้อ + อีกหนึ่งหน้า ทุกแบบใช้ธีม Warm Slate · Noto Sans Thai · สีส้มตัวเดียว · ข้อมูลแถวตัวอย่างอ้างอิงฟิลด์จริงจาก API

ทิศทาง: A · รางโปรไฟล์ B · ศูนย์บัญชี C · สมุดรายการ D · ภาพรวมบัญชี หมายเหตุกลาง
A รางโปรไฟล์ — Profile Rail ต่อยอดโครงปัจจุบัน · SEAGM-school

แถบซ้ายกลายเป็น "แผงตัวตน" จริง ๆ — รูปโปรไฟล์ ชื่อบัญชี เครดิตคงเหลือ และเมนูพร้อมตัวเลขนับ ส่วนเนื้อหาเพิ่มบริบทที่หายไปของหน้าคำสั่งซื้อ: ภาพเกม ชื่อแพ็กเกจ และ UID ที่ซื้อ — สแกนหาออเดอร์เก่าเจอเร็วขึ้นโดยไม่ต้องเปิดทีละใบ

  • จำเจนี่สุด ปลอดภัยสุด — โครงเดิมของเว็บ ผู้ใช้เรียนรู้ใหม่น้อยที่สุด
  • แผงซ้ายให้ตัวตน + เครดิตติดตาตลอด พร้อม badge นับรายการ
  • แถวคำสั่งซื้อมีภาพเกม + UID — หาออเดอร์เจอเร็วไม่ต้องเดาจากเลขที่
  • พื้นที่แนวตั้งของเมนูยาว 7 รายการ — จอเตี้ยอาจต้องเลื่อน
  • หน้า /dashboard ยังเปิดมาที่คำสั่งซื้อตรง ๆ ไม่มีภาพรวม
B ศูนย์บัญชี — Account Hub แถบบัญชีบน + แท็บ + บัตรใบเสร็จ

ตัดแถบซ้ายทิ้ง — บัญชีเริ่มที่ "แถบตัวตน" ด้านบน: รูป ชื่อ และตัวเลขสำคัญ 3 ค่าเรียงแนวนอน แล้วสลับหน้าด้วยแท็บ คำสั่งซื้อเปลี่ยนจากแถวสั้นเป็น บัตรใบเสร็จ ที่มีแถบความคืบหน้า (ชำระเงิน → กำลังส่งมอบ → ส่งมอบแล้ว) ให้กับออเดอร์ที่กำลังดำเนินการ

  • ภาพรวมติดหน้าจอ — แถบบัญชีให้ตัวเลขสำคัญตลอดเวลา ไม่ต้องเข้าหน้าเครดิต/คูปองทีละหน้า
  • แถบความคืบหน้าบนออเดอร์ที่กำลังดำเนินการ = ลด ticket "เงินหายไหม" ตั้งแต่ที่หน้าจอ
  • ไม่มีแถบซ้าย — เนื้อหากว้างเต็มพื้นที่ ตาราง/บัตรจัดวางสบาย
  • แถบบัญชี + แท็บกินความสูง ~150px ก่อนถึงเนื้อหาแถวแรก
  • แท็บ 7 อันต้องเลื่อนแนวนอนบนมือถือ (จัดการด้วย overflow scroll)
C สมุดรายการ — Ledger statement แบบแอปธนาคาร · ตารางเดี่ยว

พื้นที่บัญชี = สมุดรายการเงินของคุณ เหมือน statement แอปธนาคาร: หัวบัญชีเล็ก ๆ + ตารางเดี่ยวหนาแน่น ตัวเลข mono ชิดขวา สถานะเป็นตราปั๊มเหลี่ยม พื้นที่ว่างน้อยที่สุด เห็น 10–15 รายการต่อจอ สแกนหาออเดอร์เก่าได้เร็วสุดในทุกแบบ

  • แน่นและเร็ว — เห็นรายการเยอะสุดต่อจอ เหมาะกับผู้ใช้ซื้อบ่อยที่ต้องการ "เช็คยอด"
  • รวมเงินเข้า-ออก (ซื้อ + คืนเครดิต) ในสมุดเดียว เข้าใจง่ายเหมือน statement
  • เสียง "ร้านเติมเกม = ธุรกรรมจริง" ให้ความน่าเชื่อถือแบบ fintech
  • ดูเป็นทางการ — ความอบอุ่น/เฟรนด์ลี่ต่ำกว่าแบบอื่น
  • บนมือถือต้องพับตารางกลับเป็นการ์ด (คอลัมน์ซ่อนอัตโนมัติ)
D ภาพรวมบัญชี — Overview Home /dashboard กลายเป็นหน้าบ้าน + บัตรกระเป๋าเงิน

เปลี่ยนพื้นที่บัญชีให้เป็น "หน้าบ้าน" ของลูกค้า: เปิดมาเจอบัตรกระเป๋าเงิน (เครดิต + ตัวเลขสำคัญ) แล้วคือสรุปทุกอย่างที่ลูกค้าสนใจ — คำสั่งซื้อล่าสุด คูปองที่ใช้ได้ รายการโปรด — แต่ละการ์ดลิงก์ไปหน้าเต็ม หน้าย่อย (คำสั่งซื้อ/ใบเสร็จ/แจ้งเตือน) ใช้โครงเรียบต่ำ ๆ ให้ภาพรวมเป็นพระเอก

  • เล่าเรื่องได้มากสุด — ลูกค้าเปิดบัญชีแล้วเห็นทุกอย่างในหน้าเดียว มีที่ไปต่อทันที
  • บัตรกระเป๋าเงินสีส้ม = จุดจำของพื้นที่บัญชี + ดันคูปอง/เครดิตให้ถูกใช้จริงมากขึ้น
  • คำสั่งซื้อล่าสุด + สถานะเด่น ลดการเปิดหน้าคำสั่งซื้อเพื่อแค่เช็คของถึงไหน
  • ต้องสร้างหน้าใหม่ (/dashboard overview) + เรียก API หลายตัวพร้อมกันตอนเปิด
  • ภารเยอะกว่าในการ implement — สามแบบแรกใช้หน้าเดิมปรับ shell พอ

หมายเหตุกลาง — ใช้ร่วมกันทุกแบบที่เลือก

  • หน้าคำสั่งซื้อ → รายละเอียด (order detail), ใบเสร็จ, บัญชี, รายการโปรด จะได้ภาษาเดียวกับแบบที่เลือกทั้งหมด
  • empty state ทุกหน้าจะถูกออกแบบใหม่เป็นแบบ "ชวนลุย" (ปุ่มไปเลือกเกม / รับคูปอง) แทนกล่องข้อความเปล่า
  • ตัวเลขนับ (badge, จำนวนคำสั่งซื้อ, เครดิต) มาจาก API จริงที่มีอยู่แล้วทุกตัว — ตัวเลขใน mockup เป็นตัวอย่าง
  • ภาพเกมในแถวรายการ: ใช้ imageUrl จริงเมื่อมี ไม่มีจะ render ปกอัตโนมัติจาก GameCover (สีตาม DNA ของเกม) เหมือนหน้าแคตตาล็อก
  • ทุกแบบ responsive ลงมือถือ: A/D ยุบเมนูเป็นแถวเลื่อนแนวนอน, B ใช้แท็บเลื่อน, C พับตารางเป็นการ์ด
